# РЕГЛАМЕНТ РАБОТЫ АГЕНТА В ПРОЕКТЕ (GEMINI.md)

Настоящий регламент определяет правила автономной работы, точки обязательного согласования и протокол Git-синхронизации для AI-агента в проекте Weather Alpha Bot.

================================================================================
1. РЕЖИМ АВТОНОМНОСТИ (ТИХИЙ ХОД)
================================================================================
- Не запрашивай разрешений на рутинные действия: чтение файлов, парсинг данных внешних API (Open-Meteo, NOAA, Polymarket), запуск тестов (pytest, py_compile), форматирование, исправление мелких ошибок в коде.
- Выполняй правки файлов напрямую через tool calls в рамках утвержденного технического задания.

================================================================================
2. ОБЯЗАТЕЛЬНАЯ ПАУЗА (СТОП-КРАН НА РАЗВИЛКАХ)
================================================================================
Остановись и запроси короткое подтверждение разработчика ТОЛЬКО в критических случаях:
1. **Изменение архитектуры или структуры таблиц SQLite (`positions.db`):** удаление/переименование таблиц, деструктивные миграции, сброс пользовательских данных.
2. **Кардинальное удаление ключевых модулей бота:** удаление любых существующих `.py` файлов из кодовой базы.
3. **Изменение инфраструктуры деплоя:** модификация портов Health-Check сервера (порт 10000), смена хостинг-провайдера (Render / Dockerfile / procfile), удаление сетевых интерфейсов.

================================================================================
3. ПРАВИЛО GIT-СИНХРОНИЗАЦИИ
================================================================================
- При начале новой сессии автоматически проверяй наличие обновлений через `git pull origin main`.
- После завершения крупных правок подготавливай коммит и напоминай/выполняй `git push origin main`, чтобы удаленный репозиторий и Render всегда были актуальны.

================================================================================
4. ФОРМАТ ПАУЗЫ (STOP-BRAKE TEMPLATE)
================================================================================
При срабатывании стоп-крана ответ агента должен строго содержать:
1. **Суть действия (2–3 предложения):** «Что делаю и зачем» с указанием конкретного файла и технической причины.
2. **Конкретный вопрос разработчику:** однозначный вопрос, требующий ответа «Да/Нет» или выбора варианта действия перед применением изменений.
